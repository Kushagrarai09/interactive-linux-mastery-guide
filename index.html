History & Evolution of Linux
From a student's hobby project to powering the entire internet — the most important software story of the 20th century.
📅 Timeline of Linux
1969 — UNIX Born
Ken Thompson & Dennis Ritchie create UNIX at AT&T Bell Labs.
Written in C — the first truly portable OS. Foundation for everything.
1983 — GNU Project
Richard Stallman launches GNU (GNU's Not Unix) — free software OS.
Creates essential tools (gcc, bash, etc.) but kernel missing.
1991 — Linux Kernel Born
Linus Torvalds (21-year-old Finnish student) posts to Usenet: "I'm doing a (free) operating system..."
Linux kernel version 0.01 — 10,239 lines of code.
1994 — Linux 1.0
First stable release. 176,250 lines of code. GPL licensed.
Community of developers worldwide begins contributing.
2003 — Enterprise Adoption
Red Hat Enterprise Linux, IBM begins supporting Linux on mainframes.
Google, Amazon start building on Linux. Web era ignites.
2008 — Android
Google releases Android — built on the Linux kernel.
Linux now in every pocket on the planet.
2024 — Linux Today
Linux kernel 6.x — 30+ million lines of code. 4,000+ developers.
Powers AWS, GCP, Azure, all supercomputers, AI training clusters.

Module 02 · Core Concepts
Filesystem Hierarchy Standard
In Linux, everything is a file — even devices, processes, and network sockets. The FHS defines where things live. Learn this and Linux makes perfect sense.
📁 The Linux Directory Tree
/ ← root of everything
├── bin/ Essential user commands (ls, cp, mv, cat)
├── sbin/ System admin commands (fdisk, iptables, init)
├── etc/ Config files — /etc/nginx/, /etc/passwd, /etc/hosts
├── home/ User home dirs — /home/john/, /home/jane/
├── root/ Home directory of the root (superuser)
├── var/ Variable data — logs (/var/log), mail, databases
├── tmp/ Temporary files — cleared on reboot
├── usr/ User programs, libraries, docs
├── usr/bin/ Non-essential user commands
└── usr/lib/ Libraries for /usr/bin programs
├── lib/ Essential shared libraries (like .dll on Windows)
├── dev/ Device files — /dev/sda (disk), /dev/null (void)
├── proc/ Virtual FS — running processes, kernel params
├── sys/ Virtual FS — kernel & hardware info
├── mnt/ Temporary mount point for filesystems
├── media/ Auto-mounted removable drives (USB, CD)
├── opt/ Optional/third-party software
└── boot/ Bootloader, kernel images — vmlinuz, grub
💡 Key Concepts to Remember
▸ Everything is a file — even your keyboard is /dev/input/event0
▸ No drive letters — no C:\ or D:\ — everything is under /
▸ Case-sensitive — File.txt ≠ file.txt ≠ FILE.TXT
▸ Hidden files — start with a dot: .bashrc, .ssh/
▸ Symlinks — like shortcuts: ln -s /real/path /shortcut

File Permissions & User Management
Linux is multi-user by design. Every file has an owner and permissions. Understanding this is critical for security and system administration.
🔐 Decoding File Permissions

PERMISSION COMMANDS
$ chmod 755 script.sh # rwxr-xr-x — owner: all, others: r+x
$ chmod +x deploy.sh # Add execute permission
$ chmod -R 644 /var/www/ # Recursively set 644
$ chown john:staff file.txt # Change owner and group
$ chown -R www-data /var/www/ # Web server ownership

# USER MANAGEMENT
$ useradd -m -s /bin/bash john # Create user with home+shell
$ passwd john # Set user password
$ usermod -aG sudo john # Add john to sudo group

uid=1001(john) gid=1001(john) groups=1001(john),27(sudo)
$ who # Who is logged in?
$ sudo su - # Switch to root user

BASH FUNDAMENTALS
#!/bin/bash # Shebang — tells OS to use bash

# Variables
NAME="Linux Student" # No spaces around =
AGE=21
echo "Hello, $NAME! You are $AGE years old."
Hello, Linux Student! You are 21 years old.

# Command substitution
CURRENT_DATE=$(date +%Y-%m-%d)
FILES_COUNT=$(ls /home | wc -l)
echo "Today: $CURRENT_DATE | Home dirs: $FILES_COUNT"

# Special variables
$0 = script name
$1 $2 $3 = command-line arguments
$# = number of args $? = last exit code
$$ = current PID $* = all args as string
CONTROL FLOW
# IF-ELSE
if [ $AGE -ge 18 ]; then
  echo "Adult"
elif [ $AGE -ge 13 ]; then
  echo "Teenager"
else
  echo "Child"
fi

# FOR LOOP
for server in web1 web2 web3; do
  echo "Pinging $server..."
  ping -c 1 $server
done

# WHILE LOOP
COUNT=1
while [ $COUNT -le 5 ]; do
  echo "Attempt $COUNT"
  (( COUNT++ ))
done

# Comparison operators
-eq (==) -ne (!=) -lt (<) -gt (>) -le (<=) -ge (>=)
-f (is file) -d (is dir) -z (empty string) -n (not empty)
FUNCTIONS & BEST PRACTICES
# Define a function
greet_user() {
  local name=$1 # local = variable inside function only
  echo "Welcome, $name! $(date +%H:%M)"
  return 0
}
greet_user "Alice"
Welcome, Alice! 14:30

# Error handling with set
set -euo pipefail # Exit on error, undefined vars, pipe fail

# Logging pattern
log() { echo "[$(date '+%Y-%m-%d %H:%M:%S')] $*"; }
log "Deployment started"
[2024-01-10 14:30:00] Deployment started
🚀 Mini Project: System Health Check Script

Build a real script used by sysadmins daily!

health_check.sh
#!/bin/bash
set -euo pipefail

echo "====== SYSTEM HEALTH REPORT ======"
echo "Date: $(date)"
echo "Host: $(hostname)"
echo ""

# CPU Load
CPU_LOAD=$(cat /proc/loadavg | awk '{print $1}')
echo "CPU 1-min load: $CPU_LOAD"

# Memory
free -h | grep Mem | awk '{print "RAM: "$3" used of "$2}'

# Disk Usage
df -h / | awk 'NR==2 {print "Disk: "$3" used of "$2" ("$5")"}'

# Check if nginx is running
if systemctl is-active --quiet nginx; then
  echo "[OK] nginx is running"
else
  echo "[ALERT] nginx is DOWN!"
fi

echo "=================================="

Process Management
A process is any running program. Linux can run thousands simultaneously. You need to start, stop, monitor, and prioritize them.
PROCESS COMMANDS
$ ps aux # All processes (all users, full details)
USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND
root 1 0.0 0.1 169 12 ? Ss Jan10 0:01 /sbin/init
john 1234 2.5 5.0 512 480 pts/0 S+ 14:00 0:05 python3 app.py

$ top # Interactive process monitor (q to quit)
$ htop # Better version of top (install first)

$ kill 1234 # Send SIGTERM (graceful stop)
$ kill -9 1234 # SIGKILL — force kill (no mercy)
$ pkill nginx # Kill by process name
$ killall python3 # Kill all processes named python3

# Background / Foreground
$ ./backup.sh & # Run in background
$ jobs # List background jobs
$ fg %1 # Bring job 1 to foreground
$ nohup ./server.sh & # Run immune to logout
$ nice -n 10 ./job.sh # Run with lower priority

Module 04 · Advanced
Security, SSH & Firewalls
A Linux server exposed to the internet is attacked within minutes. Proper security configuration is not optional — it's survival.
🔑 SSH — Secure Shell
# Connect to remote server
$ ssh user@192.168.1.100 # Password login
$ ssh -i ~/.ssh/mykey.pem user@server # Key-based login

# Generate SSH key pair (DO THIS FIRST!)
$ ssh-keygen -t ed25519 -C "your@email.com"
Generating public/private ed25519 key pair.
Enter passphrase: ****

# Copy key to server
$ ssh-copy-id user@server # Auto-copies ~/.ssh/id_ed25519.pub

# Harden /etc/ssh/sshd_config
PermitRootLogin no # Never allow root SSH
PasswordAuthentication no # Keys only
Port 2222 # Change default port
AllowUsers john deploy # Whitelist users
🧱 UFW Firewall (Ubuntu)
$ sudo ufw status # Check firewall
$ sudo ufw enable # Enable firewall
$ sudo ufw allow 22/tcp # Allow SSH
$ sudo ufw allow 80/tcp # Allow HTTP
$ sudo ufw allow 443/tcp # Allow HTTPS
$ sudo ufw deny 3306/tcp # Block MySQL from outside
$ sudo ufw allow from 10.0.0.0/8 # Allow private subnet
Module 04 · Advanced
Docker & Containers
Docker packages your app + its dependencies into a portable "container" — works the same everywhere. The most important tech skill in modern DevOps.
🐳 Container vs VM — What's the Difference?
Virtual Machine (VM)
▸ Full OS per VM (2-4GB RAM each)
▸ Boot time: 1-2 minutes
▸ Strong isolation
▸ Hypervisor required
Docker Container
▸ Shares host kernel (MBs of RAM)
▸ Boot time: milliseconds
▸ Process isolation
▸ Just Docker Engine
DOCKER COMMANDS
$ docker pull nginx # Download image
$ docker run -d -p 80:80 --name web nginx # Run nginx
$ docker ps # List running containers
CONTAINER ID IMAGE COMMAND STATUS PORTS
a1b2c3d4e5f6 nginx "/docker-entrypoint" Up 2 minutes 0.0.0.0:80->80/tcp
$ docker exec -it web bash # Get shell inside container
$ docker stop web && docker rm web # Stop and remove
$ docker logs -f web # Follow container logs

# Dockerfile — build your own image
FROM python:3.11-alpine
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["python", "app.py"]

$ docker build -t myapp:1.0 .
$ docker run -d -p 5000:5000 myapp:1.0

⚠️ Common Mistakes to Avoid
✗ Running everything as root — use sudo only when needed
✗ rm -rf / or rm -rf /* — destroys everything (use carefully!)
✗ Not taking snapshots/backups before major changes
✗ Copying commands from internet without understanding them
✗ Only reading — you MUST practice in a real terminal daily
✓ Always test changes on a dev/VM before production
✓ Use man [command] to read the manual for any command
